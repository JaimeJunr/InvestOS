Gerador de Workspace

Prioridade: P0 — fundacional. Sem esta feature, nenhuma outra tem onde viver.

User Stories

US-001 — Como operador do InvestOS, quero rodar um comando de setup que cria uma pasta de portfólio novo com estrutura padrão, para não montar isso manualmente a cada portfólio.

  • Blocked by: (none)
  • AC: gera <slug>/CLAUDE.md, <slug>/_memoria/, <slug>/.env (vazio), <slug>/.claude/settings.json (plugins vazios por padrão), <slug>/.gitignore incluindo .env.
  • AC: comando é idempotente — não sobrescreve portfólio existente sem confirmação explícita.

US-002 — Como operador, quero que o setup pergunte interativamente quais domínios habilitar (research, risco, dados de mercado, corretora/banco) e quais mercados (BR/US/ambos), para personalizar o portfólio sem editar arquivos à mão.

  • Blocked by: US-001
  • AC: setup pergunta sim/não por domínio; resposta grava quais plugins/MCPs ficam habilitados em settings.json.
  • AC: mercado escolhido (BR/US/ambos) fica registrado em config própria do portfólio.

US-003 — Como operador, quero nomear o portfólio (slug) na criação respeitando o mesmo contrato de nomes usado no resto da ferramenta, para manter consistência.

  • Blocked by: US-001
  • AC: nome digitado (ex.: "Meu Portfolio") é normalizado automaticamente (slugify: minúsculas, espaços/acentos→hífen) antes de validar contra ^[a-z0-9][a-z0-9/-]{0,78}[a-z0-9]$, sem // nem .., máx. 80 caracteres.
  • AC: só é rejeitado (com mensagem explicando o valor recebido + o formato esperado) se, mesmo após a normalização, o resultado ainda violar o regex (ex.: nome vazio, ou composto só por caracteres inválidos).

US-004 — Como operador, quero gerar um segundo portfólio sem que ele interfira no primeiro (memória, config, credenciais isoladas), para validar que a estrutura suporta N portfólios mesmo usando só 1 agora.

  • Blocked by: US-001, US-002
  • AC: dois portfólios gerados lado a lado não compartilham _memoria/ nem .env.
  • AC: cada portfólio tem seu próprio .claude/settings.json.

Functional Requirements

  1. Comando cria a pasta <slug>/ com CLAUDE.md, _memoria/, .env, .claude/settings.json, .gitignore.
  2. Setup interativo pergunta, por domínio (research/risco/dados/corretora) e por mercado (BR/US/ambos), se deve habilitar — grava resposta na config do portfólio.
  3. Nome digitado é normalizado (slugify) e então validado contra o regex do contrato Ralph antes de qualquer escrita em disco; só rejeita se a normalização não resolver.
  4. Se a pasta já existir, o comando avisa e exige confirmação explícita antes de sobrescrever.
  5. .env nasce vazio e é sempre listado no .gitignore do portfólio.

Scope

In: geração da pasta, setup interativo de domínio/mercado, estrutura de config, validação de slug, idempotência.

Out: instalação de fato dos plugins escolhidos (feature Catálogo de Plugins); integração real com MCPs de dados/corretora (demais features).

Technical Considerations

Implementação (shell script tipo bin/setup.sh do BizOS, vs. skill/slash command do Claude Code) é decisão de implementação — não trava este PRD.

Dependencies

Nenhuma — feature fundacional. Catálogo de Plugins, Dados de Mercado, Gestão de Portfólio/Risco e Integração com Corretora dependem da estrutura gerada aqui.
