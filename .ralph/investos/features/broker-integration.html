Integração com Corretora/Banco

Prioridade: P2 — a mais sensível das 5 (credenciais de conta real). Substitui gradualmente o holdings manual da feature Gestão de Portfólio e Risco.

User Stories

US-001 — Como investidor, quero conectar minha conta de corretora/banco (Plaid ou Interactive Brokers) em modo read-only, para que os holdings do portfólio sejam alimentados automaticamente em vez de digitados manualmente.

  • Blocked by: plugin-catalog (entrada corretora/banco), portfolio-risk US-001 (consome holdings)
  • AC: pelo menos 1 MCP do catálogo (Plaid ou Interactive Brokers) integrado.
  • AC: acesso é estritamente read-only — nenhuma escrita/ordem possível via essa integração.

US-002 — Como investidor, quero que as credenciais dessa integração fiquem isoladas no .env do portfólio específico, nunca compartilhadas entre portfólios nem versionadas, para reduzir a superfície de risco de vazamento.

  • Blocked by: workspace-generator US-001 (contrato de .env gitignored)
  • AC: credenciais lidas só do .env local do portfólio; nenhum log ou arquivo de config em texto plano grava a credencial.

US-003 — Como investidor, quero poder desconectar/revogar a integração a qualquer momento sem afetar as outras features do portfólio, para não ficar "preso" à integração.

  • Blocked by: US-001
  • AC: remover a credencial do .env volta o portfólio a usar holdings.json manual (fallback já existente na feature Gestão de Portfólio e Risco), sem quebrar as demais features.

Functional Requirements

  1. Integração é sempre read-only — nenhuma escrita, nenhuma ordem de compra/venda via essa integração (reforça o non-goal do epic; é a única feature com acesso a dinheiro real).
  2. Credenciais vivem exclusivamente no .env do portfólio, nunca logadas em texto plano.
  3. Holdings importados dessa integração alimentam o mesmo holdings.json consumido pela feature Gestão de Portfólio e Risco — sem formato paralelo.
  4. Falha de conexão (token expirado, corretora fora do ar) degrada com aviso claro, mantendo o último holdings.json conhecido (com aviso de idade do dado) em vez de zerar a carteira.
  5. Desabilitar a integração (remover credencial) não quebra as demais features — o portfólio volta a usar holdings manual.

Scope

In: leitura read-only de posições/saldo via Plaid ou Interactive Brokers, isolamento de credenciais, fallback pra manual ao desconectar ou falhar.

Out: qualquer escrita/execução de ordem; múltiplas contas de corretora simultâneas no mesmo portfólio (v1 = 1 conexão por portfólio); suporte a todo provedor do catálogo de uma vez (ampliação é update futura).

Dependencies

Gerador de Workspace (contrato .env), Catálogo de Plugins (entrada corretora/banco), Gestão de Portfólio e Risco (consome holdings.json).

Requirements Checklist

  • Está definido que a integração é estritamente read-only, sem exceção?
  • Está definido o isolamento de credenciais (só .env do portfólio, nunca logado)?
  • Está definido o comportamento de fallback ao desconectar ou falhar a conexão?
