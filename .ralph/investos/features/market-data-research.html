Dados de Mercado e Pesquisa

Prioridade: P1. Cobertura BR informada por spike de viabilidade — sem plugin/MCP de terceiro pronto para BR, resolvido com implementação própria sobre brapi.dev + CVM Dados Abertos.

User Stories

US-001 — Como investidor, quero consultar cotação e fundamentals de ativos US/global (ações, ETFs) via MCP do catálogo, para embasar research sem sair do Claude Code.

  • Blocked by: workspace-generator US-002, plugin-catalog US-001
  • AC: pelo menos 1 MCP do catálogo (ex.: Alpha Vantage) integrado e funcional quando domínio "dados de mercado" + mercado "us" ou "ambos" (enum de workspace-generator US-005) estão habilitados no setup.
  • AC: "integrado e funcional" significa config declarativa — <slug>/.mcp.json referencia o MCP escolhido do catálogo, credencial fica como placeholder em <slug>/.env (mesmo padrão de workspace-generator US-001); testes verificam a estrutura do config, não fazem chamada de API real (definido em prd-update-1.html).

US-002 — Como investidor, quero consultar cotação de ações/ETFs/FIIs brasileiros via brapi.dev, para ter cobertura de mercado BR mesmo sem MCP de terceiro pronto.

  • Blocked by: workspace-generator
  • AC: client de brapi.dev integrado (free tier, 15.000 req/mês); cache local evita estourar a quota.
  • AC: funciona para os 4 tickers gratuitos (PETR4, VALE3, MGLU3, ITUB4) e para demais tickers com token de cadastro gratuito.
  • AC: fallback opcional via yfinance (.SA) documentado, sem quota garantida.

US-003 — Como investidor, quero consultar dados de fundos brasileiros (PL, cota, captação/resgate) via dados abertos da CVM, para research de fundos sem depender de contrato ANBIMA Feed.

  • Blocked by: US-002
  • AC: parser do Informe Diário de Fundos da CVM (dados.cvm.gov.br, CSV/ZIP) integrado, atualização batch diária.
  • AC: usuário informa o(s) fundo(s) de interesse (watchlist); parser filtra só esses no processamento diário.

US-004 — Como investidor, quero rodar skills de research (screener, fundamentals, comps, DCF simplificado) sobre os dados disponíveis, para decisão informada sem montar planilha manualmente.

  • Blocked by: US-001, US-002, US-003
  • AC: pelo menos 1 skill de research funcional por mercado habilitado (BR e/ou US, conforme setup).

Functional Requirements

  1. Client brapi.dev com cache local (evitar estourar 15.000 req/mês) e fallback yfinance .SA documentado.
  2. Parser de CSV/ZIP do Informe Diário CVM, execução batch diária, filtrado pela watchlist de fundos do usuário.
  3. Integração com pelo menos 1 MCP US/global do catálogo (ex.: Alpha Vantage) para research fora do Brasil.
  4. Skills de research (screener, fundamentals, comps, DCF simplificado) habilitadas conforme domínio/mercado escolhido no setup.
  5. Falha de dados (API fora do ar, rate limit atingido) degrada com mensagem clara — nunca trava silenciosamente nem retorna dado desatualizado sem avisar a idade do dado.

Scope

In: brapi.dev + parser CVM (mercado BR), MCP US/global do catálogo, skills de research básicas, cache e tratamento de rate limit.

Out: dados em tempo real de alta frequência (tick-by-tick), execução de ordem, cripto/forex no v1, distribuição licenciada B3 (fora de alcance de projeto pessoal — ver spike).

Technical Considerations

brapi.dev exige cache local por causa da quota mensal; CVM é batch diário (nunca intraday) — ambos documentados em spikes/dados-mercado-br.md.

Dependencies

Gerador de Workspace (estrutura/config), Catálogo de Plugins (MCP US/global), spike dados-mercado-br.md (evidência da fonte BR).
