Gestão de Portfólio e Risco

Prioridade: P1. No v1, holdings entram manualmente (arquivo no portfólio) — integração automática de posição real fica pra depois, quando a feature Integração com Corretora/Banco existir.

User Stories

US-001 — Como investidor, quero ver a alocação atual do meu portfólio (por classe de ativo/mercado) a partir das posições registradas, para saber se estou dentro da estratégia definida.

  • Blocked by: market-data-research US-001, US-002 (preços para valorizar posições)
  • AC: relatório de alocação atual vs. alocação-alvo definida pelo usuário.
  • AC: funciona com posições registradas manualmente (arquivo holdings.json no portfólio) já no v1, sem depender de integração de corretora.

US-002 — Como investidor, quero calcular métricas de risco (VaR, Sharpe, drawdown) sobre o histórico do portfólio, para entender o risco real da carteira, não só o retorno.

  • Blocked by: US-001
  • AC: VaR histórico, Sharpe ratio e max drawdown calculados a partir do histórico de preços disponível (BR via brapi/CVM, US/global via MCP do catálogo).

US-003 — Como investidor, quero receber uma sugestão de rebalanceamento quando a alocação atual desviar da alocação-alvo além de um limite configurável, para não deixar a carteira desviar sem perceber.

  • Blocked by: US-001
  • AC: sugestão de rebalanceamento (comprar/vender X para voltar ao alvo) gerada quando o desvio ultrapassa um threshold configurável por portfólio.
  • AC: a skill nunca executa ordem — só sugere (herda non-goal do epic).

Functional Requirements

  1. Holdings do portfólio registrados em arquivo próprio (holdings.json) dentro da pasta do portfólio — populado manualmente no v1.
  2. Alocação-alvo configurável por portfólio, com threshold de desvio que dispara a sugestão de rebalanceamento.
  3. Métricas de risco (VaR histórico, Sharpe, max drawdown) calculadas sobre o histórico de preços das posições.
  4. Rebalanceamento é sempre sugestão textual/relatório — nunca execução de ordem.
  5. Cálculos degradam graciosamente quando falta histórico de preço suficiente (ex.: ativo novo) — avisa a limitação em vez de travar ou inventar número.

Scope

In: alocação atual vs. alvo, métricas de risco básicas (VaR/Sharpe/drawdown), sugestão de rebalanceamento em texto.

Out: execução de ordens; otimização avançada de portfólio (ex.: Markowitz) — candidato a update futura; holdings automáticos via corretora (isso é a feature Integração com Corretora/Banco, que substituiria o arquivo manual quando existir).

Dependencies

Dados de Mercado e Pesquisa (preços/histórico), Gerador de Workspace (estrutura). Complementável depois por Integração com Corretora/Banco.
