InvestOS

C — Contexto

InvestOS é um "sistema operacional" para investimentos construído sobre Claude Code, no mesmo espírito do BizOS (harness para pequenos negócios brasileiros): uma pasta por portfólio, com memória persistente (CLAUDE.md + _memoria/), gerada por um setup interativo que personaliza quais domínios de investimento entram naquele portfólio específico. Diferente do BizOS, o InvestOS não parte de zero — cura e integra plugins/skills/agents/MCPs já públicos do ecossistema Claude Code voltados a finanças e investimento (pesquisa de mercado feita nesta sessão: anthropics/financial-services como referência mais madura, além de dezenas de repositórios de trading/quant/dados de mercado). Uso inicial é pessoal (uma carteira), mas a estrutura já nasce multi-portfólio para reuso futuro.

Personas

  • Investidor individual (usuário primário, v1) — usa o InvestOS para gerenciar a própria carteira: pesquisa, monitoramento de risco, dados de mercado, eventualmente posição real via corretora/banco.
  • Operador do InvestOS — quem gera um novo portfólio (pasta) e escolhe, no setup, quais domínios/plugins habilitar para aquele portfólio. No v1 é a mesma pessoa que o investidor.

I — Impacto esperado

Problem & Goals

  • Hoje, montar um ambiente de investimento assistido por IA significa escolher e integrar manualmente dezenas de plugins/skills fragmentados — o InvestOS resolve isso com um gerador que cura e personaliza essa escolha por portfólio.
  • Objetivo do v1: gerar um portfólio pessoal funcional, com pelo menos research + dados de mercado ativos, em uma sessão de setup.

Non-Goals

  • Não recomenda investimento nem executa ordens de compra/venda — mesmo disclaimer herdado dos plugins de terceiros pesquisados (ex.: anthropics/financial-services).
  • V1 não gerencia múltiplos portfólios simultaneamente ativos e populados — só valida que a geração funciona para mais de um; hoje só 1 portfólio pessoal é de fato usado.
  • Não expõe credenciais de corretora/banco fora do .env local do portfólio.
  • Não cria plugins novos do zero para cada domínio — cura e integra o que já existe publicamente.

Success Metrics

  • Um portfólio novo (research + dados de mercado) fica utilizável em uma única sessão de setup.
  • Pelo menos 1 plugin/skill/MCP curado e funcional por domínio (research, risco, dados, corretora) — no domínio "dados de mercado", isso é satisfeito via MCP curado (ex.: Alpha Vantage) para US/global; a cobertura BR é implementação própria (brapi.dev + CVM), não plugin de terceiro, conforme o spike.
  • Portfólio pessoal do usuário rodando ponta a ponta com research + dados de mercado ativos.

A — Alinhamento

High-Level Risks & Dependencies

  • Dependência de marketplaces/repositórios de terceiros (podem sumir, mudar de dono, ou perder manutenção) — mitigado por curadoria com critério explícito (ver feature Catálogo de Plugins).
  • Credenciais de corretora/banco são superfície sensível mesmo isoladas em .env gitignored por portfólio.
  • Fragmentação do ecossistema (muitos plugins com escopo sobreposto) — risco de escolha ruim sem critério de curação definido.

Requirements Checklist

  • Está definido o mecanismo de personalização por portfólio (setup interativo)?
  • Está definido onde e como credenciais sensíveis são armazenadas?
  • Está definido o escopo de ativação real do v1 (quantos portfólios populados)?
  • Está definido se existe um plugin "core" obrigatório ou se tudo é opcional?

Assumptions

  • ASSUMPTION: nenhum plugin de terceiro pesquisado (financial-services, trading-skills, quant, MCPs de dados/corretora) foi testado nesta sessão — a curadoria descrita aqui é baseada em pesquisa web (READMEs), não em instalação/uso real. Validação real acontece na feature-level de cada domínio.
